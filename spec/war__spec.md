## Data Structures

State root (target; `state.war` today has `units, armies, garrisons?, wars, score, sieges, occupations, blocs`):
```js
state.war = { units: Record<Id, Unit>, armies: Record<Id, Army>, garrisons: Record<provId, Garrison>, wars: War[], score: WarScoreEntry[],
              sieges: Record<provId, {besieger, progress, since}>, occupations: Record<provId, {occupier, since, rebel?}>, blocs: Record<Id, Bloc>,
              standing: StandingEntry[],              // standing_share dial entries {scope, value, declaredTurn}; resolved with kernel resolveState
              templates: Record<countryId, Record<Id, SortingTemplate>>,   // player-authored; shipped ones in ruleset.war.sortingTemplates (Default)
              showOfForce: Record<`${country}|${target}`, ModifierStack>,  // replaces `training`
              techTier: Record<countryId, 'cold_steel'|'gunpowder'> }
```

### Technology Tier
Code: none
- `state.war.techTier[country]` (and optional province override); `techModifier(tier)` multiplies Armor speed penalty; gunpowder gives `effectiveness *= 1 + T('war.gunpowder.bonus') × u.supply` (cut off → degrades toward/below cold-steel baseline). Ruleset pool `combat` blocks carry the cold-steel base; no second roster.

### Army Roster
Code: `ctx.ruleset.pools[pool].kind === 'army'`, `pools[pool].combat` (generated by `tools/buildRuleset.mjs` as placeholders)
- Six Army pools: Shock Infantry, Pike Infantry, Skirmishers, Cavalry, Artillery, Siege Corps. Mages are drawn on Meteomancy/Theurgy and appear as a Contingent with `pool: 'Mage'` and tag `ritual` **(target; no Mage pool in code)**.
- Variants are Estate/culture/tech modifiers, never new pools.

### Fielded Unit (Standing Commitment)
Code: `actions.js` (`fieldUnits.apply`), `stock.js` (`regionStock`, `takeRegionStock`)
```js
// today (code): Unit {id, army, originCell, pool, n, cohesion, supply, wounded:[{n, returnTurn}]}      // one pool per Unit already
// target (a Contingent):
Unit = { id, army, originCell: CellKey, pool, n /*count*/, mustered /*ceiling for Reinforcement*/, kind: 'levy'|'standing',
         equipmentTier, armorInvested /*0..1*/, cohesion, supply /*0..1*/, wounded: [{n, returnTurn}],
         stance: 'balanced', detachment: 'vanguard'|'center'|'rearguard' }
Army = { id, owner, units: Id[], position, prev, destination, path[],       // today
         tactic: 'balanced'|'aggressive'|'defensive', stance:'hold', traits:[] }   // today (army-wide)
Army(target) = { …, entrySide, routeSide, depths: {vanguard, center, rearguard}, tactic: {vanguard, center, rearguard}, src, pathSevered }
```
- **(spec decision)** The kb's `army.contingents.{vanguard,center,rearguard}` is a derived grouping of `army.units` by `unit.detachment`; `units` stays the flat list.
- `fieldUnits {originCell, composition: {pool: n}, at?}` (commitment, gate `retinue`, public): validates (origin cell belongs to the Country; pools are army pools; free labour per pool; muster point inside the origin Region; `MilitaryCap` axis; Cold Weapons in the recruiting Region ≥ `men × war.field.goodsPerMan`), then commits `labourCommitted[pool] += n`, takes the goods once from the Region's warehouses, and creates **one unit per pool**. Acquisition today: market purchase of goods only (Requisition override: Economics/polity).
- **Casualties**: `hit()` splits loss into Killed (`1 − war.wounded.share`; permanent: deducted from `cell.labour`, `cell.labourCommitted`, `cell.population`) and Wounded (`war.wounded.share`; `returnTurn = turn + war.wounded.delay`); `recover()` returns the wounded into `u.n`. Captured: open (post-alpha). Disbandment returns labour at once (`disbandArmies` for blocs; no player `disband` action in code **(gap)**).
- `fieldUnits` stays as the single-cell, explicit-composition building block (AI — War uses it); `mobilize` (below) applies the kb's total-obligation and 10% rules.

### Levy, Standing Army and Mobilization (2026-11-10)
Code: none (target)
```js
// standing_share: dial entries, resolved per cell (most specific scope wins, kernel resolveState)
standingShare(ctx, key) = resolveState(state.war.standing, key, ctx) ?? 0
setStandingShare {scope, value:0..1}     // dial; gate 'retinue' (spec decision: domain for armed-force Rights); public; also reachable as a cell petition Question (polity)
mobilize {scope: cell|Region|Empire, templateId, at?}     // commitment; public; gate 'retinue'
demobilize {scope}                                         // releases the commitment; labour returns at once
mobilizedTotal(cell) = duty(cell,'Levy') × compliance(cell).involuntary          // Levy Duty from polity (ctx.derive.polity.duty), compliance from polity
standingPart(cell)   = mobilizedTotal(cell) × standingShare(cell)  -> kind 'standing', rest -> kind 'levy'   (same pool shares)
```
- Covered cells: `cellsCovered(scope)`; Region is the default scope, Empire = every cell of the Country, cell = single cell. Each covered cell contributes by its own obligation × compliance; cells resist through their permitted/granted/defiance actions (no loyalty stock).
- Upkeep: a `standing` unit's upkeep goods are drawn as for any unit, with `war.standing.upkeepMult` > 1 applied to its `upkeep`; the cost is debited from the **origin cell's** Wealth and goods (not the Government Ledger) **(spec decision; needs an Economics hook: `upkeepBySource` must carry `payer`)**. The Government may subsidise through its spending dial (`standingSubsidy` item, polity); the uncompensated part is `ctx.derive.war.standingBurden(cellKey)`, read by polity into `burden_share` and the entitlement-loss acceptance function.
- Same Combat Envelope, Supply, Casualty rules for both kinds; levy labour returns to production on demobilize (no peacetime claim); standing keeps `labourCommitted` in peace.
- **(spec decision)** Mobilize creates one army per Region at that Region's muster point (default: the Region's province with the highest presence of the cell's Nation); a Region scope with several covered cells puts all their Contingents in one army; Empire = one army per Region. Open in kb.

### Retinue Right and military contribution (2026-11-10)
Code: `internal.js` (`retinueScalar`, `retinueComposition`) for the armed rung only; contribution boost: none (target)
```js
militaryContribution(cell, pool) = baseContribution(cell, pool) × (1 + T('war.retinue.k') × retinue(cell))   // pool ∈ {Shock Infantry, Pike Infantry, Skirmishers, Cavalry, Siege Corps}; never Artillery, Meteomancy/Theurgy
retinue(cell) = clamp01(Number(ctx.derive.polity.right(key,'Retinue') ?? 0))
```
- The boost raises the cell's **generation** of those pools (Economics pool output reads `ctx.derive.war.retinueBoost(cell, pool)`), so it feeds `pool_share` indirectly; it is **not** applied again at sorting or fielding and is not a Fairness term. **(spec decision)** hook location: Economics labour-generation step.
- Armed-rung role unchanged (see Internal Armed Conflict). Open in kb: whether Siege Corps stays in the boost list.

### Contingents and Army Composition (2026-11-10)
Code: none (target); today `fieldUnits` takes an explicit composition and `fight()` ignores detachments
```js
// generation (mobilize)
poolShare(cell,p)    = cell.labour[p] / Σ_army cell.labour[q]      // (spec decision) labour generated, Retinue boost already inside
contribution(cell,p) = mobilizedTotal(cell) × poolShare(cell,p)
exists(cell,p)       = contribution ≥ T('war.contingent.minShare') × mobilizedTotal(cell)  ||  p ∈ {Artillery, Siege Corps, Mage}      // minShare = 0.10 (settled)
// a share below the threshold is simply not deployed: those people stay in production
```
```js
// sorting (autoSort(army, template)): whole Contingents only; capacity counted in troops
SortingTemplate = { name, shares: {vanguard, center, rearguard}, vanguard_rules: Rule[], rearguard_rules: Rule[] }
Rule = {take_all: pool} | {take_share_of_remaining: [pool, f]} | {fill_ratio: {pool: weight}}
capacity(d) = shares[d] × Σ n over the army's Contingents
sort(army, t):
  unassigned = army.units ordered by (pool order of the rule, then id)           // deterministic
  for d of ['vanguard','rearguard']:                                             // priority Vanguard → Rearguard → Center
    for rule of t[d + '_rules']:  assign whole Contingents while remaining capacity ≥ unit.n (a Contingent that does not fit stays unassigned and falls to the next lower detachment)
        take_all(p):                   every unassigned Contingent of pool p
        take_share_of_remaining(p,f):  Contingents of p in order until Σn ≥ f × (unassigned troops of p), or capacity is full
        fill_ratio(w):                 repeatedly pick the pool most below its target share Σtaken(p)/w(p); add its next Contingent that fits; stop when none fits
  center = every Contingent still unassigned (may exceed shares[center])
  each assigned unit.detachment = d
```
- Default template (settled) shipped in `ruleset.war.sortingTemplates.Default`: shares 0.20 / 0.60 / 0.20; vanguard `take_all(Cavalry)` → `fill_ratio({Skirmishers:2, 'Shock Infantry':1})`; rearguard `take_share_of_remaining(Cavalry,0.30)` → `fill_ratio({Skirmishers:3,'Shock Infantry':1,'Pike Infantry':1})`; center everything left.
- Templates are player data (`state.war.templates[country]`, CRUD outside the simulation: no Decision Log entry); the chosen template is a parameter of `mobilize`, `fieldUnits` (optional), `mergeArmies`, `splitArmy`, and of `resortArmy {armyId, templateId}` (event; re-sorts the whole army and **overrides manual reassignments**). The simulation only sees `unit.detachment`.
- Stance: `unit.stance = 'balanced'` always in alpha (no modifiers); AI — War may change it (`ai_war__spec.md`, Reserved interface). Tactic is per detachment (Army Tactics).
- **Reassign** `reassignContingent {armyId, unitId, to}`: dial-class command, legal only if `|depth(from) − depth(to)| ≤ depthTolerance(min(speed(unit.pool), slowest speed in the receiving detachment))`.
- **Depth tolerance** `depthTolerance(S) = T('war.tol.base') × S / T('war.speed.ref')` (relative speed; quicker troops → larger tolerance). Alpha: speed only; terrain and obstacles post-alpha.
- **Merge** `mergeArmies {from, into}` (commitment): legal iff same owner, same province and, for each detachment d, `dist(position(A,d), position(B,d)) ≤ depthTolerance(min(armySpeed(A), armySpeed(B)))`; the detachments are concatenated separately (`unit.army = B`, `unit.detachment` kept); then the army is not re-sorted.
- **Position (derived, proposed reading)**: `position(army,d)` = point on the segment from the entry-edge midpoint through the province centre at fraction `depth(d)` (centre at 0.5 for every `entrySide`); distance Euclidean in hex units (centre = origin, edge midpoint at radius 1). Same entry side → difference of depths; opposite sides cannot merge. The merged army keeps B's `entrySide` and takes the troop-weighted average of the derived positions per detachment (projected back to depth).
- **Split** `splitArmy {armyId, unitIds}` (commitment): only whole Contingents; the parent keeps ≥ 1; the new army starts at the parent's position, `entrySide`, `routeSide` and `depths`; each moved unit keeps its detachment.
- Multi-origin stacking Coordination cost (Administration) is unchanged; merge/split do not change origin tracing.
- **Consequence to confirm (kb)**: a Contingent larger than a detachment's remaining capacity falls down whole, so Vanguard or Rearguard can end up empty.

### Reinforcement (proposed — 2026-11-11)
Code: none (target); runs in `step4` after `recover()`
```js
for u of units where army.pathSevered === false:        // `supply()` sets army.pathSevered = (src distance ≥ 99); today it only sets supply 0
  deficit = u.mustered − u.n − Σ u.wounded.n
  gain    = min(deficit, T('war.reinforce.rate') × u.mustered, free(cell,pool))      // free = cell.labour[pool] − cell.labourCommitted[pool]
  u.n += gain;  cell.labourCommitted[pool] += gain                                  // the cell's own pool; population/burden reach grievance through the existing Levy/casualty channels
```
- Same Contingent, same detachment, no re-sort; never above `mustered`; no goods cost until `war.reinforce.goods` (open) is set; a severed supply path or an empty pool means no gain.

### Traits & Interactions (sparse tags)

### Terrain Combat Modifier
Code: `combat.js` (`terrainMod = ruleset.terrain[terrain].combat[pool] ?? 1`)
- Favours: Grassland/Steppe → Cavalry; Mountain/Hill → Pike/Shock (def), Siege Corps (immobile), penalises Cavalry; Wetland/Jungle/high forestation → Skirmishers, penalises Cavalry and Artillery; Desert/Arctic only via Supply decay. `forest_movement` overrides the forest hard-block for movement.

### Army Position & Maneuver
Code: `graph.js` (`stepAllowed`, `findPath`, `bfsDistance`), `step.js` (`moveArmies`), `actions.js` (`orderMove`)
```js
// today: army.position = provId; path/destination; reroute = new orderMove
stepAllowed(ctx, a, b, army) -> false | {cost}      // Mountain↔Mountain blocked unless pass; forest hard-block at forestation ≥ war.forest.block unless forest_movement; river crossing costs war.river.cost; hard fortress blocks until reduced
moveArmies: steps = max(1, floor(speed × (0.5 + infra/100)))          // (code-led) speed = slowest unit of the army; edge quality gates progress
            stop when entering a province with an enemy army or an enemy-controlled province
armySpeed(target) = min(speed(Center), speed(Rearguard))              // Vanguard exempt (target; code uses the slowest unit)
edgeQuality = province.infrastructureLevel × edgeTypeModifier         // gates the ATTACKER on its committed route; defenders use the full network (code: attacker/defender distinction not yet implemented)
```
- Target adds `entrySide`, `routeSide`, `depths`: depth advances along the route; reroute is always legal, costs a full turn with zero progress. Formation cohesion gate: `spread = max(depths) − min(depths)`; above `war.spread.max` the closest pair fights first and the rest are delayed or miss. Detection: Vanguard composition vs terrain concealment. Stacking uncapped.
- **Detachment roles** (strategic, not a battle line): Vanguard — detection, harassment, screening (Compel), local foraging/requisition; Center — battles and sieges; Rearguard — intercepts supply-route raids, prevents encirclement, keeps broken main forces in order, can itself be scattered under the same spread gate. Numbers open (numbers pass).

### Evasion / Compel
Code: none
1. Gate: attacker `armySpeed` must threaten interception.
2. Compel: Vanguard vs Vanguard by `screening_strength = discipline × reachBonus × tacticMod`; defender wins → clean disengage; attacker too weak → deflected; attacker wins → battle at current depths.
3. Rearguard raids: a separate, cheaper supply-interdiction order; the defender's **Rearguard** intercepts through the same `screening_strength` contest.

### Supply
Code: `step.js` (`supply`), `module.js` (`upkeepBySource`), `ctx.services.economics.draw`
```js
// per army each turn: nearest friendly source by BFS over own/occupier-controlled provinces (distance d, 99 = none)
base = d ≥ 99 ? 0 : clamp01(1 − T('war.supply.decay') × d × (1 − T('war.supply.infraRelief') × infra/100))
need[good] = Σ upkeep[good] × u.n;  got = min over goods of draw(src, good, qty) / qty        // real zero-sum draw from the supply zone's market (service economics.draw)
u.supply = clamp01(base × got);  u.cohesion −= 0.02 when u.supply < 0.5
army.src = nearest source province       // read back by Economics next turn as military demand (upkeepBySource)
```
- **(code-led)** supply sources are provinces owned and controlled by the army's owner or occupied by it (no Warehousing-sufficiency check; no Diplomacy access-granted territory yet); interdiction by occupation works through `controller()`; besieging the source does not yet cut the path.
- Wartime Requisition override and Vanguard local requisition (two Opinion hits toward the occupier): Economics/polity; not in code. Alpha naval: sea lanes carry transport and supply only (Naval scope).
- Target: `army.pathSevered` set here (feeds Reinforcement); `standing` units' upkeep payer (Mobilization).

### Siege State
Code: `step.js` (`sieges`)
```js
garrison = T('war.garrison.perPop') × province.population;  fort = 1 + (# fortress edges at p)                      // (code-led) stand-ins for fortification level / garrison strength
siegeStr = Σ u.n × (combat.siege ?? 0.2) × u.supply;  def = T('war.siege.defRate') × garrison × fort × 10
ratio = clamp((rate×siegeStr − def)/(rate×siegeStr + def), −0.5, 1)
progress += T('war.siege.capture') / T('war.siege.turns') × ratio;  progress = max(0, progress)                     // ≈ `turns` turns when the besieger dominates
logScore(cause 'siege', cells of p, {turns:1}) every turn;  at progress ≥ capture → occupation (or liberation if the owner retakes a bloc-held province)
```
- Sally, Relief, Assault: not in code. A siege starts when an army sits in an enemy-controlled province with no enemy army present.

### Battle Resolution (sequential, state carries forward)
Code: `combat.js` (`fight`), `step.js` (`clashes`)
```js
fight(ctx, A, D, province) -> {winner:'A'|'D', score:{A,D}, log:[{cell,killed,wounded}], rout}
  pairs units largest-first (by n, then id); per pair: skirmish (ranged power × flank × harassment vs melee) then melee (power × flank × interaction); casualties via hit() (Killed/Wounded split)
  rout phase: score = Σ n×cohesion; winner cohesion += war.cohesion.win, loser −= war.cohesion.loss; loser aggregate cohesion < war.rout.threshold → pursuit casualties ∝ speed ratio × war.pursuit
clashes: attacker = the army that arrived this turn; loser retreats to `prev` or is deleted below 1 man; every log entry becomes a per-cell war-score entry
```
- **(code-led)** pairing is by unit size, not by detachment; no screening-strength contest, no sub-unit paired duels beyond the pair loop, no Rearguard effects, no gunpowder conditional, no per-round trace. Cohesion persists per unit, bounded [0,1], never reset.
- Target: detachment-aware pairing (Vanguard/Center/Rearguard roles), screening contest (mounted bypass vs forced reach engagement), `flankingBonus` from cascading reinforcement, Rearguard prevents encirclement and keeps routs orderly.
- **Tactic stances** (Balanced · Hold Formation · Aggressive · Cautious · Flanking-focused): stance is automatic per Contingent and Balanced in alpha; modifiers table in `ruleset.war.stances`.

### Army Tactics

### Internal Armed Conflict (handed off from Internal Politics — settled 2026-11-01)
Code: `internal.js`, `armedRevolt` cell action, `tests/internal_conflict.test.js`
- Bloc: `state.war.blocs[id] = {id, country, need, goal: 'concession'|'independence', cells[], formed, secure, calm, status: active|conceded|suppressed|seceded}`; internal war record `{a: parent, b: blocId, internal: true}` so `atWar`, armies, sieges and peace work unchanged. Membership is the cell flag `flags.rebel = blocId` (survives Region re-derivation).
- Rebel units: `retinueComposition(cell)` = free pool labour × Retinue scalar, limited by Cold Weapons in the cell's Region; mustered by `muster()` as ordinary units (tactic `defensive`).
- Rebel supply: provinces whose `occupations[p].occupier` is the bloc (home provinces seized at the uprising).
- End states in `stepInternal` (step 4): suppression (no armies, nothing held → `endBloc 'suppressed'`), concession (all member rungs 0 for `civil.calm.turns`, or peace terms), secession (all home provinces held and free of Government armies for `civil.secede.turns` → `formCountry`).
- `armedRevolt` (cell action; class commitment, `cellAvailability: 'permitted'` with a Retinue check in `propose`; public): utility `civil.revolt × grievance × (1 − involuntary) − defy.risk × involuntary`; needs rung ≥ 4 and `men ≥ civil.minMen`. **(code-led)** the kb/actions table calls it `armedRung`.

### Show of Force (formerly Troop Training — 2026-11-10)
Code: none (target); old `troopTrainingTick` is retired
```js
state.war.showOfForce[`${country}|${target}`] : ModifierStack          // target = Country or Bloc
feed (step 4, after movement):  for each army of `country` stationed in a border Region adjacent to `target` and no active war between them:
  push(stack, {value: T('war.show.k') × troopCount(army) × efficiency(army), decay:{kind:'exp', rateKey:'war.show.decay'}, turn})
inBorderRegionAdjacent(army, target) = army's province lies in a Region owned by army.owner that has a province sharing an edge with a province owned by target

Decays after withdrawal or when a war begins; Diplomacy's Military Leverage reads it (`diplomacy` readout, evaluated at negotiation time against the target and its Alliance-tier partners); stacks additively with exhaustion/active-war penalties.
- `actions__spec.md` still lists `troopTraining`: remove with the next kb amendment.

### Occupation (canonical — War-triggered, consequences owned elsewhere)
Code: `step.js` (`sieges`, `W.occupations`), `module.js` (`occupiedShare`), `internal.js` (`controller`)

### Occupation garrison (soft, substitutable — settled 2026-11-02)
Code: none for occupation; `martialCost` implements the civil-war variant
```js
garrisonDemand(cell)   = T('war.garrison.perPop') × cell.population × (1 + cell.grievance.occupation)
martialLawControlCost  = T('war.martialLaw.control') × cell.population × shortfallFraction(garrisonDemand, troopsPresent + controlSubstitute)
uprisingThreshold      = T('war.uprising.base') × (1 + (occupied ? T('war.martialLaw.raise') : 0)) × (1 − unmetGarrisonFraction)    // unmet garrison LOWERS the trigger threshold
```
- No fixed number, no hard requirement; troops and Control are interchangeable; sizing derived from population and grievance.

### War Score (computed ledger, not spendable — revised 2026-11-01)
Code: `step.js` (`logScore`), `module.js` (`warScore`)
```js
logScore(ctx, {cause, side, cells, harm}) -> state.war.score.push({…, turn})      // causes in code: 'battle', 'siege' (kb also lists blockade, raid)
warScore(ctx, side) = Σ over entries: +k if e.side === side && target ≠ side; −k if e.side ≠ side && target === side      // k = harm.killed ?? harm.turns; target = owner of the entry's first cell
```
- Per-cell harm in existing stocks; no Loyalty stock, no persistent Faction; every entry tags cells; never spendable; context only. Attribution: harm goes to the enemy by default; a cell blames its own Government only when the causal role is very obviously incompetent (polity Awareness). **(code-led)** entries carry `cells: [key]` (kb: `target_cells`) and `harm` fields `killed/wounded/turns`.

### War Exhaustion (derived, per-cell — revised 2026-11-01)
Code: `module.js` (`exhaustion`, `countryExhaustion`), `step.js` (`recover`)
- **(code-led, differs from kb)** code stores a decaying `cell.warHarm` (`+war.harm.k × loss/pop` per casualty batch, `+war.occ.harm × occupiedShare` per turn, decay `war.harm.decay`) that feeds the Security grievance, and `exhaustion(cell)` just reads it. The kb says Exhaustion is a read-only derived readout of war-attributable grievance, not stored. Needs a decision: keep `warHarm` as polity-owned input to grievance and define Exhaustion over the resulting war-attributable grievance, or move the stock out of War.
- `countryExhaustion` = population-weighted mean; never an input to simulation mechanics. Crossing the Question trigger can spawn a peace Question regardless of the cell's original stance or Veto (polity).

### Peace Conference (capability assessment, not War Score arithmetic)
Code: `module.js` (`peaceEvaluation`, handler `war.peaceResolve`), `actions.js` (`proposePeace`)
```js
peaceEvaluation(side, enemy, terms) = stance(side, terms, ctx, {
  selfInterest: (0.5 − own/(own+foe)) + war.peace.exh × countryExhaustion(side) − war.peace.cede × cede + war.peace.cede × gain − war.peace.treaty × (# treaty terms imposing on side),
  modifier: 1 + war.peace.scoreWeight × tanh(warScore(side)/50) })                // WarScore is context only
```
- Flow: `proposePeace {war, terms:{cede:[{province,from,to}], treaties:[…]}}` (event, gate `war`, public) → scheduled step 7 `war.peaceResolve`; the proposer accepts its own terms, the receiver judges with `approves(peaceEvaluation(...))`; on acceptance install treaties (`diplomacy.installTreaty`), cede provinces, remove both sides' occupations, `w.active = false`. `lastProposal = {turn, accepted}`. Tests: `tests/war.test.js` (accepted by a weak/exhausted side; refused by a strong one).
- **Proposal stacks (target)**: `terms` becomes `stack: [{terms, class: 'obligatory'|'optional'}]`, no size limit; the receiver evaluates each proposal with `peaceEvaluation`; an obligatory proposal that is refused means no agreement from that stack; optional ones are accepted or refused individually; mirrored for both sides. The session rules (no fixed term, withdrawal restarts, satisfaction meter) are Diplomacy's Negotiation Session, reused **(proposed reading in kb)**. Today: single `terms`, receiver-only evaluation.
- Veto-to-declare and Veto-to-continue share one stance function: `declareWar.impact` uses `warHarm`; same `stanceFns` for `declareWar` and continue.
